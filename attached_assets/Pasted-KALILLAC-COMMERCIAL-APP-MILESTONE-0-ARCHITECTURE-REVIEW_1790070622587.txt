PRODUCT PURPOSE

Kalillac is not “another ChatGPT wrapper.”

Its primary commercial identity is:

Private by default. Save only what you choose.

Supporting promise:

Powerful AI without automatically turning every conversation into a permanent record.

The product should provide the polished AI experience people expect from major consumer AI applications while retaining substantially less conversation data by default.

NON-NEGOTIABLE PRIVACY MODEL

Temporary Chat is the default.

A user must be able to chat without creating a Kalillac username, password or email profile.

Unsaved conversation content may exist while active only in:

* device memory
* temporary backend RAM/session state
* a model/search provider request when required to answer

Temporary conversation content must NOT be written to:

* PostgreSQL
* Supabase
* SQLite
* AsyncStorage
* SecureStore
* iCloud
* a conversation-history database
* analytics
* crash-report payloads
* session replay
* permanent application logs
* a vector database
* persistent document storage

Temporary chats must never touch Supabase/Postgres.

There must be explicit session destruction plus server-side TTL for abandoned sessions.

Saving is an explicit user action:

Save this chat

For v1 this means:

Save on this iPhone

Saved chats should be encrypted locally.

Do not build cloud chat sync in v1.

AI EXPERIENCE

Default mode:

Auto

Manual modes:

Fast
Smart
Deep

Planned production model strategy:

Fast → Groq gpt-oss-120b, with Groq Zero Data Retention enabled

Smart → OpenAI GPT-5.6 Luna, with store=false for temporary conversations

Deep → OpenAI GPT-5.6 Terra, with store=false for temporary conversations

Auto → server-side Kalillac routing based on task difficulty, required tools, files/images, current-information requirements, cost, privacy and context.

Do not send every request to the most expensive model.

Prefer deterministic/local processing where appropriate.

SEARCH PRIVACY

A search provider must never receive the full conversation.

Intended path:

user request
→ Kalillac backend derives minimal search query
→ search provider receives only that query
→ retrieved results return
→ necessary snippets plus necessary conversational context are sent to the AI model
→ answer contains citations

Brave Search API is currently preferred if its commercial terms are suitable. Tavily is an acceptable alternative.

TEMPORARY ATTACHMENTS

PDFs, documents and images must follow the temporary-chat privacy model.

Prefer:

* RAM when practical
* encrypted temporary storage only when necessary
* random object identifiers
* file type/size validation
* short TTL
* automatic cleanup

No temporary attachments in Supabase Storage.

No vector database for temporary content.

Avoid provider file APIs that persist files when direct request processing can be used instead.
